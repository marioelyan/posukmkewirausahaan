# Multi-Business Phase 4C — CRM & Loyalty Isolation (Implementation Notes)

Status: **Phase 1–3 documented; targeted hardening applied.** Backend/security only — no frontend, DB schema, route, or config changes. All fixes are guarded by `config('multi_business.enabled')` and remain inert in legacy mode.

`MULTI_BUSINESS_ENABLED` default unchanged. No migrations, seeders, backfill, or deployment run. No `.env` touched.

## 2. Fail-closed invariants applied

- **Customer**: `BelongsToBusiness` global scope + `creating` hook (existing). Web/API route binding uses scoped query.
- **TenantUnique** (new `App\Support\Tenancy\TenantUnique`): `Rule::unique(...)->where('business_id', ...)` under tenancy, else legacy; fails closed with no context. Applied to web `CustomerController` (store/update), `MemberController` (update), API `CustomerController` (store/update). Prevents cross-business duplicate probing and preserves flag-off behavior.
- **CustomerSegmentMembership** (model): added `booted()` global scope `business_via_customer` constraining to customers in active business via `Customer::query()->select('customers.id')`. Fails closed (no context) via customer scope. Protects `memberships()` counts/aggregates and any direct membership query.
- **CustomerSegmentController**: all actions guard via `ensureSegmentsManageable()` → `abort(404)` when `multi_business.enabled` is true. Consistent with 4A (segments fail closed). `syncSegments` on `CustomerController` also aborts 404 under tenancy to avoid cross-business manual membership ops. `CustomerSegmentationService::segmentOptions()` and `serializeCustomerSegments()` return `[]` under tenancy (defensive).
- **CustomerVoucherController**: `canUseVoucher` returns false for null-outlet vouchers under tenancy; `scopeVouchersToActiveOutlet` drops null-outlet and restricts to active outlet under tenancy (fail closed if no outlet). `customer_id` validated with `BelongsToActiveBusiness('customers')`. Preserves legacy (null-or-active-outlet) when disabled.
- **CrmCampaignController**: `canUseCampaign` under tenancy rejects null-outlet campaigns and uses `accessibleOutlets` for all roles (removes superadmin bypass). Added `scopeCampaignsToActiveOutlet` mirroring voucher scoping (fail closed). Index/store/edit/show/process/cancel/log actions use scoped access.
- **CrmReminderController**: under tenancy `includeLegacy=false` and `outletIds` constrained to `accessibleOutlets` for all roles (including superadmin); reminder query already filters by outletIds+legacy condition (legacy only when flag off).
- **Customer history/aggregates**: `CustomerController::buildStats/recentTransactions/frequentProducts` and `MemberController` equivalents now scope `Transaction::query()` to active business warehouse ids via new `OutletAccessService::activeBusinessWarehouseIds()` (returns `null` when disabled; empty collection → `whereIn` yields no rows when enabled with no context). Prevents indirect cross-business read of transactions belonging to B even if customer_id references B (defense in depth).
- **API customers**: uniqueness validation uses `TenantUnique` (scoped to active business) when tenancy enabled; behavior unchanged flag-off.

## 3. Background context & deferred items

- **Queued/scheduled jobs**: `crm:sync-segments`, `crm:generate-reminders` run without business context. Under tenancy, `Customer::query()` returns empty (fail closed) — acceptable as a fail-closed stance and explicitly flagged for a future Jobs/Scheduler build (tenant propagation per-iteration). No queue tenant middleware or job scoping added.
- **CustomerSegment membership global scope**: added via `whereIn(customer_id, Customer::query()->select(...))`. `Customer::query()` is scoped to active business; under no context customer scope returns empty → membership scope returns empty (fail closed). This is correct for web requests with `business.required`.
- **LoyaltyPointHistory**: no global scope added. Access paths audited: `whereHas('customer')` used in AdvancedSalesInsights (4A); relations `customer->loyaltyPointHistories()` safe (parent scoped). Direct `LoyaltyPointHistory::count()` remains global — documented as a read-surface that must not be used to enumerate across businesses; controller/service surfaces fixed. Not adding a model global scope avoids potential side effects on creation/joins; requirement is satisfied at access boundaries.
- **Global unique codes**: `customer_vouchers.code` and `customer_segments.slug` have global unique DB constraints (preserved). `generateVoucherCode()` uses `CustomerVoucher::query()->where('code',$code)->exists()` — under tenancy with a customer-scope global on vouchers (none added), this is global. No change to preserve constraint semantics. Segment slug uniqueness check global (controller) — segments fail closed under tenancy so mutations don't occur.
- **PriceList customer_segment_id**: no change; segments fail closed under tenancy so references to segments are effectively non-existent in tenant context (frontend won't see segments; existing logic unchanged).
- **Merge/duplicates feature**: no such feature exists in codebase — documented as `does not exist` (Phase 16). REST CRM/Loyalty surface: only `api/v1/customers` exists (already constrained by abilities and tenancy middleware). No REST endpoints for segments/campaigns/vouchers — documented as `No REST CRM/Loyalty surface currently exists` where applicable.

## 4. Compatibility & verification

- Flag-off: all new guards return early when `multi_business.enabled` is false (legacy preserved). TenantUnique behaves identically to `unique` when disabled.
- Middleware: dashboard routes under `['auth','business','business.required']` (existing) — context required under tenancy; no middleware changes.
- Tests: new `tests/Feature/Business/CrmLoyaltyIsolationTest.php` covers core invariants (customer scope/creation, voucher null-outlet fail-closed, segment controller fail-closed, campaign outlet scoping, membership scope excludes foreign customers, document history boundary). Existing 4A/4B tests remain unaffected.
- Commands: background CRM commands unchanged (fail-closed under tenancy) — consistent with deferred tenant propagation.
